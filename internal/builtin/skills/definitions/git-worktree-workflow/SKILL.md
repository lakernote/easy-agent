# Git worktree workflow

1. 创建前确认仓库根目录、当前分支、工作区改动、现有 worktree 和目标基线；已有改动默认属于用户，不能移动、覆盖或重置。
2. 一个独立任务使用一个分支和一个 worktree。分支名、目录名和任务标识保持可追踪；不要让两个运行中任务写入同一个 worktree。
3. 从明确的基线提交创建分支；如果基线或目标分支会实质改变结果，先说明当前证据并请求确认。
4. 依赖安装和构建缓存可以共享只读来源，但输出目录、临时文件和进程必须留在各自 worktree，避免跨任务污染。
5. 合并前检查两边状态和测试结果，区分代码冲突、生成文件冲突与环境冲突，不用强制重置掩盖问题。
6. 只有 worktree 已停止使用、改动已提交或明确放弃时才清理；删除分支、丢弃改动或强制移除必须得到明确授权。
