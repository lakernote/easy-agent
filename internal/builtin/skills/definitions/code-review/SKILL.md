# Code review

1. 先确认审查范围：目标变更、调用方、数据边界、兼容要求和已有测试；代码位于服务器时，使用 `shell` 的 `pwd`、`rg`、`sed`、`git diff` 等命令读取真实仓库，不要只看孤立 Diff。
2. 优先检查会造成错误结果、崩溃、数据丢失、权限绕过、并发问题或兼容性破坏的行为，不做纯风格挑错。
3. 每条发现必须包含可复现的触发条件、实际影响和代码证据；证据不足时写成待确认问题，不写成确定缺陷。
4. 检查新增分支是否有对应测试，并确认测试断言能够捕获该问题，而不只是覆盖代码行；能够安全运行时用 `shell` 执行相关测试并引用真实结果。
5. 输出按严重程度排序的 findings；没有发现时明确说明已检查的范围和仍未覆盖的风险。
