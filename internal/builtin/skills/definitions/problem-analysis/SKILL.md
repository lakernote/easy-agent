# Problem analysis

1. 先提取现象、发生时间、环境、最近变更、错误码、堆栈入口和 requestId/traceId 等关联标识。
2. 建立按可能性排序的少量假设，并为每个假设写出支持证据、反证和最便宜的验证方法。
3. 有本地代码或日志时用 `shell` 围绕错误文本、堆栈文件和关联标识定向搜索；有监控、Issue、Wiki 或 Git MCP 时再按需加载，避免无目的读取大量上下文。
4. 将“最后修改人”“代码所有者”和“引入根因的人”分开；只有变更与失败机制存在证据链时才建议责任人。
5. 至少用两条独立证据支持根因结论；证据不足时保留候选，并执行信息增益最高的下一项检查。
6. 最终说明：发生了什么、最可能根因、证据、影响、建议处理人、置信度和下一步。
