# Release engineering

1. 先读取仓库现有的发布说明、CI 工作流、版本来源和 Git 状态；沿用项目已经采用的发布机制，不平行发明另一套流程。
2. 明确发布版本、目标提交、支持平台和是否为预发布。检查同名 tag、Release 和产物是否已存在，重复执行必须安全失败或复用已有结果。
3. 发布前运行与风险相称的测试和构建，确认二进制报告的版本与目标一致，并检查平台、架构、文件名、校验和及必要的签名信息。
4. 发布说明只总结目标版本真实包含的用户可见变化、修复和已知限制；不要根据文件名推测功能，也不要把未完成工作写成已发布。
5. 创建 tag、推送、上传 Release 或覆盖远端产物属于外部变更，只有用户明确要求时执行；执行前再次核对版本和目标提交。
6. 最终报告发布结果、验证命令、产物位置、未覆盖平台和失败后的安全重试方式。
