# Test and E2E

1. 根据变更的责任边界选择最小但有效的测试矩阵：纯函数用单元测试，存储和 HTTP 契约用集成测试，跨前后端关键路径用真实浏览器端到端测试。
2. 先验证构建和类型检查，再运行最接近改动的测试，最后扩大到相关测试集；不要用大量无关测试代替关键行为断言。
3. E2E 使用临时数据库、隔离账号或明确的测试资源。测试数据和服务端口不能覆盖用户现有环境，结束后按用户要求保留或清理。
4. 浏览器验证至少覆盖主路径、一个相邻失败或边界路径、控制台与失败请求；涉及响应式布局时增加窄屏检查。页面问题的细节操作可加载 `browser-validation`。
5. 测试失败时保留首次失败证据，区分产品缺陷、测试缺陷、环境缺失和不稳定测试；不能只靠重复运行把偶发失败描述成通过。
6. 最终列出实际执行的命令和路径、通过结果、关键观察、未验证范围及仍需人工体验的部分。
